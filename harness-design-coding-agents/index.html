04 · Context-management techniques

Three mechanisms control what stays in the conversation

Preserve useful information while keeping active history within the model’s context budget.

Elision

Remove bulky old tool output from the visible conversation while retaining a marker.

Before: $ find . -type f [hundreds of paths] After: [Earlier output elided — 241 lines omitted]

Best for repetitive or recoverable output no longer needed verbatim.

Summarization

Replace older dialogue with a concise summary of decisions, constraints, and unfinished work.

Summary: - Goal: fix date parsing - Tried UTC conversion - Remaining: handle empty input - Tests still failing: date_spec

Keeps task state, not every original token.

Tool recall

Store full tool output separately and retrieve it later by identifier.

In conversation: Output saved as [tool: 17] Later: recall_tool_output("17") → original output restored

Recovers exact details after output leaves active context.

Combined strategy: elide old tool output first; summarize older history only when needed; preserve original outputs for recall by ID.

Source: Fan et al., context-management strategy descriptions.

05 · Finding 3 · Tool interface

Structured tools and bash-only access trade off reliability, flexibility, and cost

The study compares predefined workspace tools with a single bash tool at 128k context, with planning and combined context management enabled.

Predefined workspace tools

Separate tools expose common actions with a clear interface.

read_file(path) write_file(path, content) edit_file(path, patch) list_files(path) search_files(pattern) bash(command)

Less command construction; the harness can validate or track file operations.

Bash-only

One terminal tool provides broad composability but requires the model to build shell commands.

grep -R "pattern" . find src -type f sed -n '1,120p' file.py python -m pytest

Flexible, but success depends on correct shell workflows.
